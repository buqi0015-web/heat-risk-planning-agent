# 高温设施规划 Agent：记忆模块面试说明

## 1. 面试表达摘要

这个项目里的记忆模块定位为“项目级规划记忆”，核心任务是保存一个连续规划项目中的目标、证据、过程和版本。用户先提出治理目标，系统生成风险诊断、设施缺口、候选点和方案比选；随后用户会继续追问依据、调整约束、切换策略或生成报告。记忆模块负责保存当前项目状态、上一轮空间检索证据、任务执行过程和方案版本，让 Agent 能够复用已有分析、支持连续追问、判断局部重算范围，并保证每个输出都有证据链和追溯记录。

一句话回答：

> 我把记忆设计成项目级规划记忆，分为对话记忆、项目记忆、过程记忆和证据记忆。普通闲聊只进入对话层，不污染规划状态；空间类问题会复用上一轮 RAG 证据；约束调整会写入重算提示，明确哪些结果保留、从哪一步重算。

## 2. 为什么这个项目需要记忆

高温设施规划是连续决策过程。

典型过程：

1. 用户输入：“优先保障老人和接送学家庭，在高温风险区补充清凉设施。”
2. Agent 生成风险诊断、人群暴露、设施覆盖、缺口识别、候选点推荐和方案比选。
3. 用户继续问：“除此之外呢？”、“这个点为什么推荐？”、“避开学校门口重新算。”
4. Agent 需要知道上一轮查的是哪个范围、命中了哪些点位、当前方案采用什么策略、新约束影响哪些任务。

如果没有记忆，Agent 每次都会像第一次对话一样回答，容易出现三个问题：

- 追问断裂：不知道“还有吗”指的是上一轮缺口排行还是候选点清单；
- 结果浪费：用户改约束后无法复用风险诊断、设施覆盖等已有结果；
- 证据断裂：报告无法说明某个候选点来自哪次检索、哪条证据、哪个版本。

因此，本项目需要的是可审议的规划项目记忆，重点保存项目目标、空间证据、任务过程和方案版本。

## 3. 记忆模块总体设计

当前实现新增了 `src/agent/projectMemory.js`，将记忆拆成四个部分：

| 记忆类型 | 记录内容 | 解决的用户问题 | 是否写入规划状态 |
|---|---|---|---|
| 对话记忆 conversation | 最近输入、回答、意图路由、是否规划相关 | 支持连续追问和上下文承接 | 普通闲聊只写这里 |
| 项目记忆 project | 研究区、目标人群、设施类型、策略、约束、版本、候选点 | 支持项目上下文稳定延续 | 规划任务才更新 |
| 过程记忆 process | 任务图、工具调用、版本历史、重算提示 | 支持局部重算和方案追溯 | 规划任务和约束调整更新 |
| 证据记忆 evidence | ragMemory、空间检索范围、图层、命中对象、人工核验项 | 支持空间追问和证据链 | 空间 RAG 命中后更新 |

## 4. 四类记忆的产品价值

### 4.1 对话记忆

记录：

- 当前用户输入；
- Agent 回复；
- 意图路由；
- responseType；
- 是否规划相关；
- 是否写入项目状态。

产品价值：

- 用户问“还有吗”“继续”“这个点呢”时，系统能接住上下文；
- 普通聊天、天气、日期、问候不会修改候选点和方案；
- 面试中可以强调“防污染”：只有规划工作流会进入项目状态，普通聊天留在对话层。

### 4.2 项目记忆

记录：

- 研究区；
- 情景日期；
- 当前治理目标；
- 目标人群；
- 设施对象；
- 策略偏好；
- 空间约束；
- 当前方案版本；
- 当前候选点集合。

产品价值：

- 用户切换页面后，Agent 仍知道当前项目在做什么；
- 用户继续调整策略时，不需要重新说明研究区和目标人群；
- 方案报告能引用当前目标、策略和约束。

### 4.3 过程记忆

记录：

- taskGraph；
- reviewedTaskGraph；
- toolCallHistory；
- versionHistory；
- process events；
- recalculationHints。

产品价值：

- 支持解释“这个方案怎么来的”；
- 用户新增约束后，系统可以判断重算起点；
- 每个版本都能说明由哪个输入、哪个约束、哪些任务产生。

### 4.4 证据记忆

记录：

- 上一轮 ragMemory；
- 空间查询类型；
- 检索范围；
- retrievedLayers；
- matchedEntities；
- rankingSignals；
- manualCheck；
- dataBoundary。

产品价值：

- 用户问“除此之外呢”时，直接读取上一轮 RAG 结果；
- 用户问某个点位依据时，可以说明命中的道路、热点、候选点和排序依据；
- 数据未命中时，系统能说明当前边界，不会编造地图里没有的地点。

## 5. 写入规则与防污染机制

记忆模块的核心规则是：不同类型的问题进入不同记忆层。

| 用户问题类型 | 路由结果 | 记忆写入 | 规划状态是否变化 |
|---|---|---|---|
| “你好” | capability/general | conversation | 不变化 |
| “今天天气怎么样” | casual_weather | conversation | 不变化 |
| “哪里设施缺口最大” | spatial_rag | conversation + evidence | 不直接重跑工作流 |
| “北京林业大学附近有没有设施缺口” | spatial_rag | conversation + evidence | 不直接重跑工作流 |
| “优先保障老人，生成候选点” | planning_workflow | conversation + project + process | 更新 |
| “避开学校门口重新算” | constraint_revision | conversation + project + process | 更新版本和重算提示 |

这样做解决两个风险：

1. 普通闲聊污染规划状态；
2. 空间问题被大模型凭空回答。

## 6. 局部重算如何依赖记忆

用户新增约束时，系统会把它写入 `process.recalculationHints`。

### 例 1：避开学校门口

- 约束类型：空间排除约束；
- 可保留结果：高温风险诊断、重点人群暴露、现有设施覆盖；
- 重算起点：候选点生成；
- 影响步骤：空间约束检查、点位排序、方案比选、报告摘要。

### 例 2：步行距离小于 300 米

- 约束类型：可达性约束；
- 可保留结果：高温风险诊断、重点人群暴露；
- 重算起点：步行可达；
- 影响步骤：缺口识别、候选点生成、点位排序。

### 例 3：低成本优先

- 约束类型：策略偏好变化；
- 可保留结果：风险诊断、人群暴露、设施覆盖、缺口识别；
- 重算起点：点位排序；
- 影响步骤：方案比选、推荐方案、报告摘要。

面试表达：

> 约束调整采用局部重算。系统先判断新约束影响哪些任务，再读取过程记忆里的已有结果，保留稳定分析，只从受影响节点开始重算。

## 7. 与空间 RAG 的关系

空间 RAG 负责回答地点、道路、设施缺口、候选点和排行问题。项目记忆负责保存上一轮 RAG 的结果。

当前链路：

1. 用户提出空间问题；
2. intentRouter 判断进入 spatial_rag；
3. spatialRag 查询地图数据和候选点数据；
4. 返回 evidencePackage 和 ragMemory；
5. projectMemory 写入 evidence.ragMemory；
6. 用户追问“除此之外呢”；
7. 系统读取 projectMemory 中的 ragMemory，继续展示上一轮结果。

产品价值：

- 追问更自然；
- 答案有证据；
- 数据边界更清晰；
- 避免大模型独立判断空间事实。

## 9. 面试官可能追问

### Q1：为什么不能只保存聊天记录？

回答要点：

- 聊天记录只能说明用户说过什么；
- 规划 Agent 还需要记住项目目标、候选点、方案版本、工具调用和证据来源；
- 只保存聊天会导致追问能接上，但结果无法复用和追溯；
- 本项目采用项目级规划记忆，服务于多轮决策。

### Q2：如何避免记忆污染？

回答要点：

- 先做意图路由；
- 普通聊天只进入 conversation；
- 空间问题进入 evidence，但不直接改候选点方案；
- 规划工作流才更新 project 和 process；
- 数据未命中时记录边界，不把模型猜测写入状态。

### Q3：记忆如何支持“除此之外呢”？

回答要点：

- 上一轮空间 RAG 会生成 ragMemory；
- projectMemory 把 ragMemory 存在 evidence 中；
- 追问触发 follow_up_more；
- 系统读取上一轮 lastResults 和 shownResultCount，继续返回后续结果。

### Q4：约束调整为什么能局部重算？

回答要点：

- process 记忆保存任务过程和当前版本；
- 新约束会生成 recalculationHints；
- 系统判断可保留结果和重算起点；
- 例如“避开学校门口”保留风险和覆盖，从候选点生成开始重算。

### Q5：长期记忆会不会带来隐私风险？

回答要点：

- 当前记忆保存项目上下文和规划结果；
- 不保存用户私人偏好和无关个人信息；
- 重点是项目级规划记忆，保存对象集中在项目、证据、过程和版本；
- 后续产品化需要加权限、项目隔离和清除机制。

### Q6：为什么把记忆分成 project/process/evidence？

回答要点：

- project 解决“当前项目是什么”；
- process 解决“方案怎么来的”；
- evidence 解决“回答依据是什么”；
- 三者分开后，普通聊天、规划状态和空间证据不会混在一起。

## 10. 面试收束话术

可以这样总结：

> 记忆模块是这个 Agent 能从聊天工具变成规划工具的关键。它让系统同时记住对话、项目目标、空间证据、任务过程和方案版本。这样用户可以连续追问，可以新增约束，可以局部重算，也可以追溯每个候选点和方案的依据。对于城市规划场景，这比单纯的聊天上下文更重要。
