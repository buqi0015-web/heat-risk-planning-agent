# 高温设施规划 Agent 产品需求文档（PRD）

## 1. 产品概述

**一句话定位：** 将高温治理目标转译为空间分析任务的规划 Agent。

高温设施规划 Agent 面向基层治理人员、责任规划师和规划咨询团队，服务于城市极端高温治理中的设施布点决策。用户输入自然语言治理目标后，系统将目标拆解为空间分析任务，组织风险诊断、人群暴露、设施覆盖、步行可达、缺口识别、候选点生成、方案比选和人工核验，最终形成可审议的设施布点方案。

| 项目 | 内容 |
|---|---|
| 核心用户 | 基层治理人员、责任规划师、规划咨询团队 |
| 核心场景 | 用户提出高温治理目标后，系统生成设施布点建议和审议材料 |
| 主要价值 | 降低规划分析门槛，缩短从风险识别到治理行动的路径，沉淀可追溯证据链 |
| 最终输出 | 候选点清单、推荐理由、方案比选、证据摘要、不确定性说明、人工核验清单 |
| Demo 入口 | 本地运行后访问 `http://127.0.0.1:5175/` |

## 2. 背景与问题定义

### 2.1 基层治理需求与规划专业能力之间的断点

基层治理人员通常能描述真实问题，例如“老人多的社区需要避暑点”“学校周边接送等待太热”“公交站附近缺少遮阴”。这些表达已经包含治理目标，但还没有转化为完整的规划分析任务。

高温设施布点需要连续判断：

- 哪些区域高温风险高；
- 哪些重点人群暴露在风险中；
- 现有清凉设施是否覆盖；
- 步行距离和实际可达性是否合理；
- 哪些区域同时具备高风险、高需求、低覆盖；
- 哪些点位具备补设施或复用的条件；
- 哪些结论可以进入方案，哪些需要人工核验。

过去这些判断依赖责任规划师的经验、GIS 分析能力和多部门数据整理。产品需要降低基层用户把治理目标拆成专业任务的门槛，同时让规划师获得可复用的分析流程。

### 2.2 空间数据识别与治理行动生成之间的断点

热力图可以说明哪里热，人口密度可以说明哪里人多，POI 和设施点位可以说明哪里有服务资源。但数据本身还需要被组织为治理动作。

用户真正需要回答的是：

- 先治理哪里；
- 补什么类型的设施；
- 设施应该放在哪里；
- 推荐理由是否充分；
- 公平、效率、成本、应急之间如何取舍；
- 哪些点位必须进入现场核验。

产品目标是把“问题识别”推进到“方案生成”，让空间数据进入可审议、可追溯的治理决策链。

## 6. 产品目标与非目标

### 6.1 产品目标

- 降低基层用户拆解规划任务的门槛；
- 缩短从高温风险识别到设施布点建议的路径；
- 将规划师经验流程化；
- 将空间数据转化为治理动作；
- 支持多轮约束调整；
- 输出可审议、可追溯的方案。

### 6.2 产品非目标

- 当前阶段不替代规划师最终决策；
- 当前阶段不生成具有法律效力的正式规划成果；
- 当前阶段不确认权属、施工条件和安全责任；
- 当前阶段不直接处理真实遥感影像；
- 当前阶段不接完整真实 GIS 后端；
- 当前阶段不让大模型自由生成点位作为最终依据。

## 9. Agent 工作流

用户输入：  
“优先保障老人和接送学家庭，在高温风险区补充清凉设施。”

1. **识别治理目标**：判断用户要解决高温设施治理问题。
2. **提取结构化信息**：识别目标人群、设施对象、策略偏好和空间范围。
3. **判断任务类型**：将目标归类为候选点生成任务。
4. **检查前置条件**：确认是否已有风险诊断、人群暴露、设施覆盖和设施缺口结果。
5. **自动补齐缺失任务**：缺少前置结果时先补齐，避免直接生成点位。
6. **生成任务图**：把分析过程组织为有依赖关系的任务链。
7. **执行计划审查**：检查任务输入、依赖关系和风险边界。
8. **按依赖执行任务**：依次完成风险诊断、人群暴露、设施覆盖、步行可达、缺口识别、候选点生成、约束检查、点位排序、方案比选和材料生成。
9. **结果写回状态**：每个任务输出进入 AgentState，供后续任务和多轮对话复用。
10. **输出审议结果**：展示候选点方案、方案比选结果和审议支持材料。
11. **支持后续调整**：用户可继续查看依据、调整约束或生成报告。

## 10. Agent 约束机制

| 约束机制 | 解决的风险 | 具体做法 | 用户价值 |
|---|---|---|---|
| 任务类型约束 | 模型误判问题类型 | 先判断风险诊断、缺口、候选点、比选、报告等任务 | 避免回答跑偏 |
| 工作流模板约束 | 跳过关键分析步骤 | 不同任务绑定标准流程 | 保证分析完整 |
| 前置条件约束 | 缺数据直接出结论 | 候选点生成前检查风险、覆盖、缺口结果 | 提升可信度 |
| 任务图约束 | 执行顺序混乱 | 用依赖关系组织任务 | 过程可解释 |
| 工具注册约束 | 随意调用能力 | 只允许调用已注册分析能力 | 控制输出来源 |
| 计划审查约束 | 错误计划进入执行 | 执行前检查输入、依赖和风险 | 降低方案错误 |
| 输出结构约束 | 结果不可审议 | 固定输出候选点、证据、核验项 | 便于汇报讨论 |
| 人工核验约束 | AI 结论被过度信任 | 权属、消防、施工、开放时间进入核验清单 | 明确责任边界 |

## 11. 状态记忆设计

### 11.1 短期记忆

记录当前用户输入、当前任务类型、临时约束、执行状态、阻塞原因和下一步建议。它用于支持“还有吗”“换一个点”“这个点为什么推荐”这类连续追问。

### 11.2 长期记忆

记录项目研究区、目标人群、设施类型、已有风险诊断、已有设施覆盖、已有候选点和已有方案结果。它用于复用既有分析，避免每轮对话都从零开始。

### 11.3 过程记忆

记录任务图、工具调用历史、输入输出记录、方案版本、新增约束、重算起点和保留结果。它用于支持局部重算和方案追溯。

记忆模块的产品价值：

- 支持多轮对话：系统知道上一轮讨论对象和空间证据；
- 支持结果复用：已有风险、覆盖、缺口结果可被后续任务读取；
- 支持局部重算：新增约束后只重算受影响任务；
- 支持方案追溯：每个版本都能说明来源和调整原因。

工具调用流程：

1. Planner 根据任务图选择工具；
2. 执行前检查输入是否齐全；
3. 工具返回结构化结果；
4. 结果写回状态；
5. 后续任务读取状态；
6. 输入缺失时触发补充任务或人工提示；
7. 当前阶段使用 mock 工具验证流程，后续替换为真实 GIS 或空间分析接口。

## 13. 约束调整与局部重算

| 用户输入 | 约束类型 | 影响步骤 | 保留结果 | 重算起点 | 新版本输出 |
|---|---|---|---|---|---|
| 避开学校门口 | 空间排除约束 | 候选点生成、约束检查、方案比选 | 风险诊断、人群暴露、设施覆盖 | 候选点生成 | 去除冲突点后的新候选清单 |
| 步行距离小于 300 米 | 可达性约束 | 步行可达、缺口识别、候选点生成 | 风险诊断、人群暴露 | 步行可达 | 300 米约束下的新缺口和候选点 |
| 低成本优先 | 策略偏好变化 | 点位排序、方案比选、推荐方案 | 风险诊断、人群暴露、设施覆盖、缺口识别 | 点位排序 | 低成本优先方案版本 |

局部重算让用户可以持续讨论方案，并快速看到约束变化带来的结果变化。

## 14. 结构化输出设计

### 14.1 候选点方案

包含候选点、推荐优先级、推荐理由、服务人群、覆盖范围和需核验事项。它服务于“设施放哪里、为什么放这里、先放哪个”的决策。

### 14.2 方案比选结果

包含公平优先方案、效率优先方案、低成本优先方案、应急优先方案、推荐方案和取舍说明。它服务于多目标治理中的策略选择。

### 14.3 审议支持材料

包含证据摘要、数据来源说明、不确定性说明、人工核验清单和下一步建议。它服务于会议讨论、部门协同和现场核验。

## 16. 评测方案

| 评测项 | 评测目标 | 评测方法 | 样例测试 | 通过标准 | 失败案例 |
|---|---|---|---|---|---|
| 需求理解准确性 | 判断用户真实意图 | 构造多类输入 | “老人多的地方补清凉点” | 正确识别目标人群和设施 | 误判为普通聊天 |
| 任务拆解完整性 | 检查任务链是否完整 | 对照标准流程 | 候选点生成任务 | 包含风险、人群、覆盖、缺口 | 直接输出点位 |
| 前置条件检查正确性 | 避免缺数据出结论 | 删除前置结果测试 | 无设施覆盖数据 | 自动补齐覆盖任务 | 跳过覆盖分析 |
| 工具选择正确性 | 调用合适能力 | 检查任务与工具匹配 | 问“哪里缺口最大” | 调用缺口识别 | 调用报告生成 |
| 状态写回正确性 | 保证结果可复用 | 检查 AgentState | 生成候选点后追问 | 能读取上一轮结果 | 追问丢失上下文 |
| 局部重算准确性 | 判断影响范围 | 新增约束测试 | “避开学校门口” | 从候选点生成重算 | 全流程重算或不重算 |
| 输出可审议性 | 结果可被讨论 | 专家打分 | 候选点方案 | 有理由、证据、边界 | 只有一句建议 |
| 人工核验项完整性 | 控制落地风险 | 核验清单检查 | 候选点推荐 | 包含权属、消防、施工 | 无核验提示 |
| 用户可用性 | 用户能否理解 | 可用性访谈 | 基层用户试用 | 能解释下一步动作 | 用户不知道如何操作 |
| 效率对比 | 验证产品价值 | 与人工流程计时 | 生成初版方案 | 明显缩短时间 | 与人工耗时接近 |

## 17. 风险与边界

| 风险 | 影响 | 缓解策略 | 是否进入人工核验清单 |
|---|---|---|---|
| 数据质量风险 | 点位推荐偏差 | 标注数据来源和时间 | 是 |
| 大模型生成不可靠 | 出现无依据结论 | 空间问题先查数据，限制自由生成 | 是 |
| 空间分析误差 | 覆盖或可达判断不准 | 保留不确定性说明 | 是 |
| 权属不确定 | 点位无法落地 | 明确需现场核验 | 是 |
| 施工条件不确定 | 推荐点不可建设 | 加入施工与安全核验 | 是 |
| 用户过度信任 AI | 方案被直接执行 | 输出定位为审议依据 | 是 |
| 规划责任边界 | 决策责任不清 | 标注人工审定环节 | 是 |
