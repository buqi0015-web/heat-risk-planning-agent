# 高温活动失效诊断与清凉设施规划 LLM Agent：技术面试深挖问答

## 使用方式

- 第一遍背诵“核心短答”，保证能够在 30 至 60 秒内讲清楚。
- 第二遍理解“继续追问”，面试官质疑技术细节时再展开。
- 回答时主动区分已完成能力、当前验证结论和未来迭代计划。
- 不将内部一致性指标描述为真实行为预测准确率。

---

## 一、开场必背

### Q1：请用一分钟介绍这个项目

**核心短答：**

我做的是一个面向责任规划师的高温活动失效诊断与清凉设施规划 Agent。传统热风险地图能够识别哪里温度高，但很难说明高温具体影响了谁、影响了什么日常活动，以及设施应该服务什么需求。

项目融合 WorldPop 人口、POI、建筑轮廓、EULUC 用地、OSM 步行路网、Landsat LST、树冠、水体和 ERA5-Land 数据，模拟居民活动链，并沿真实道路逐边累计热暴露。系统能够识别活动问题发生在出发地、路径还是目的地，再将活动失效转译为清凉设施需求。

LLM 负责居民诉求理解、受约束行为推演、多主体方案审议和规划解释；GIS、路网与规则模型负责空间事实和数值计算。当前已经完成端到端原型、量化验证、LLM 消融、设施运行约束、反事实分析和交互式展示。

### Q2：这个项目解决的核心问题是什么？

**核心短答：**

核心问题是把抽象的高温风险转化为可执行的规划问题。系统需要回答四个问题：

1. 哪类居民的什么活动受到影响；
2. 风险发生在出发地、路径还是目的地；
3. 居民为什么无法规避高温或使用附近设施；
4. 哪类清凉设施能够恢复活动并降低暴露。

### Q3：项目最有新意的地方是什么？

**核心短答：**

创新点主要有三项：

1. 将选址需求从静态人口覆盖升级为具体活动失效需求；
2. 将热暴露计算细化到居民经过的每条道路边和对应时段；
3. 使用受空间事实和行为规则约束的 LLM，连接居民自然语言、模拟证据与规划决策。

## 二、LLM 核心作用：重点必背

### Q4：LLM 在项目中到底发挥了什么作用？

**核心短答：**

LLM 的产品定位是居民需求与专业规划模型之间的语义推理层，设计承担四类任务：

1. 将居民自然语言诉求转译为人群、活动、时间约束、空间问题和设施需求；
2. 在结构化模型提供的允许动作集合内进行高温行为推演并生成理由；
3. 从老人、家长、户外劳动者和设施管理者等不同视角审议方案；
4. 将 GIS、行为模拟和反事实结果组织为规划师可审议的行动卡片。

坐标、路径、热暴露、人口和设施容量均由确定性模块计算，LLM 无权修改这些事实。

当前已经实现受约束行为动作选择、情境解释、规则校验、错误回退、决策日志和消融实验。居民自然语言诉求转译、多主体审议与规划行动卡已完成产品和 Schema 设计，属于下一阶段强化任务。

### Q5：既然行为模型已经有规则，为什么还需要 LLM？

**核心短答：**

规则模型擅长处理确定的计算边界，例如哪些动作可选、路径暴露是多少、设施是否开放。真实居民诉求通常表达模糊、约束交叉，并且包含隐含原因，例如“学校门口太晒，附近有商场但来不及进去”。LLM 可以提取其中的接送活动、固定时间、低绕行容忍和原位遮阴需求，并把模型结果转化为规划语言。

当前 LLM 的主要增量集中在语义转译、复杂情境解释和多主体审议。行为动作稳定性主要由结构化先验保障，这一点已经通过消融实验确认。

**继续追问：LLM 是否只是生成解释？**

当前版本中，LLM 已经参与允许集合内的行为动作选择，同时生成解释。消融实验显示，移除结构化先验后动作分歧率达到 41.67%，说明 LLM 会依据上下文形成不同判断。完整约束条件下，LLM 与结构化模型动作一致，表明现阶段约束保障了稳定性。下一阶段会通过居民诉求转译和多主体方案审议强化 LLM 的独立产品价值。

### Q6：为什么不让 LLM 直接完成全部行为模拟和设施推荐？

**核心短答：**

城市规划结果需要空间准确性、可追溯性和可复现性。通用 LLM 不擅长精确计算道路路径、逐边暴露、设施容量和空间距离，也可能生成不存在的地点。项目采用分层架构：

- GIS 与路网模块计算空间事实；
- 规则与概率模型控制行为边界；
- LLM 处理模糊语义、情境推理和规划表达；
- 规划师保留最终决策权。

这种分工能够发挥 LLM 的语言推理优势，同时控制幻觉和不可复现风险。

### Q7：你如何控制 LLM 幻觉？

**核心短答：**

我设计了六层约束：

1. LLM 仅接收经过清洗和计算的结构化上下文；
2. 行为动作只能从 `allowed_actions` 中选择；
3. Prompt 明确禁止生成地点、设施和数值；
4. 输出必须是固定 JSON；
5. 输出动作会再次进行规则校验；
6. API 超时、解析失败或动作违规时自动回退至结构化模型。

同时保存输入、输出、决策来源和错误日志，支持逐条审查。

### Q8：LLM 的输入和输出分别是什么？

**核心短答：**

输入是结构化活动上下文，包括居民类型、出行类型、活动必要性、时间刚性、路径平均及最大热压力、高温重合时间、清凉设施可达性、功能匹配度、绕行时间和允许动作集合。

输出是固定 JSON，核心字段包括选择的行为动作、中文理由、设施含义和不确定性说明。动作必须属于允许集合，空间事实必须来自 GIS 模块。

**输入示例：**

```json
{
  "resident_profile": "儿童照护者",
  "trip_type": "fixed_time_necessary",
  "activity_necessity": 1.0,
  "time_rigidity": 0.9,
  "route_mean_heat_stress": 0.72,
  "heat_overlap_minutes": 28,
  "cooling_match": 0.20,
  "detour_minutes": 6,
  "allowed_actions": ["normal", "risky_completion", "shorten", "add_stop"]
}
```

### Q9：受约束 LLM 是如何实现的？

**核心短答：**

系统先由结构化行为模型依据出行类型生成允许动作，并计算一个先验建议及理由。随后将活动上下文、允许动作和结构化先验传给 DeepSeek。模型使用低温度参数并要求 JSON 输出。程序解析结果后再次检查动作是否合法，任何异常都会触发结构化决策回退。

**技术细节：**

- 模型调用：DeepSeek Chat Completions API；
- `temperature = 0.2`；
- `response_format = json_object`；
- 动作白名单：`normal`、`risky_completion`、`cancel`、`delay`、`substitute`、`shorten`、`add_stop`；
- 按出行类型进一步收窄动作集合；
- 决策来源记录为 `deepseek` 或回退来源。

### Q10：为什么选择 DeepSeek？

**核心短答：**

项目当前需要中文情境理解、结构化 JSON 输出、较低调用成本和可通过 API 快速验证的模型能力。DeepSeek 满足研究原型阶段的要求。架构层面通过统一输入输出 Schema 隔离模型供应商，未来可以替换其他模型并进行横向评测。

### Q11：如何证明 LLM 在项目中有贡献？

**核心短答：**

我使用消融实验区分不同信息和模块的贡献。在同一批 12 个活动、相同随机种子下，对比四组：

1. 结构化模型；
2. 完整受约束 LLM；
3. 移除空间上下文；
4. 移除结构化先验。

动作白名单、JSON 校验与违规回退在四组实验中均正常生效。移除结构化先验后，LLM 与基线动作分歧率达到 41.67%，说明结构化先验对决策稳定性影响显著。当前小样本中，移除空间上下文没有改变动作分布，说明空间上下文增量仍需通过更复杂情景继续验证。

### Q12：完整 LLM 与结构化模型完全一致，是否说明 LLM 没有价值？

**核心短答：**

这个结果说明当前约束设计能够保证动作稳定，也说明现有测试样本对 LLM 独立决策能力的区分度不足。项目没有把一致率包装成 LLM 性能提升。

LLM 已经能够生成情境化理由。自然语言诉求转译和多主体审议是下一阶段的核心产品角色。后续会构造高热、高绕行、设施功能冲突和多主体利益冲突情景，分别评价需求转译完整率、事实一致率、冲突覆盖率和规划师采纳率。

### Q13：LLM 受规则限制后，还算 Agent 吗？

**核心短答：**

它具备感知结构化环境、基于目标选择动作、调用专业工具、记录状态并生成下一步建议的 Agent 特征。规划场景要求高可控性，因此采用受约束 Agent 架构。它的自主性体现在语义理解、情境判断、工具编排和方案审议中，行动边界由规划规则和空间事实限定。

### Q14：LLM 如何处理居民自然语言诉求？

**核心短答：**

设计流程分为五步：

1. 提取居民群体、活动目的、时间约束和痛点；
2. 推断可能的失效位置与设施需求；
3. 生成待 GIS 核验条件；
4. GIS 核验入口、路径、树冠、热环境和现有设施；
5. LLM 根据核验结果修订需求并生成规划问题卡。

输出中会区分已验证事实、模型推断和待核验项，避免把居民描述直接当作空间事实。

### Q15：多主体审议具体做什么？

**核心短答：**

同一设施方案会分别从老人、儿童照护者、户外劳动者和设施管理者视角审议。LLM 提取共同需求、利益冲突和实施条件，例如老人需要长时间停留，接送家长需要原位短时服务，管理者关心容量与开放时间。最终输出冲突清单和折中建议，供规划师确认。

### Q16：未来如何评价 LLM 的质量？

**核心短答：**

我会分四层评价：

1. 格式层：Schema 合规率；
2. 事实层：GIS 事实一致率、无依据地点生成率；
3. 任务层：需求转译完整率、待核验识别率、多主体冲突覆盖率；
4. 用户层：规划师采纳率、修改次数和任务完成时间。

同时通过移除 LLM、移除空间上下文、移除结构化先验和更换模型进行消融与对比。

### Q16.1：哪些 LLM 能力已经完成，哪些仍在规划中？

**核心短答：**

当前已完成 DeepSeek API 接入、允许动作内的行为决策、结构化先验输入、固定 JSON 输出、动作合法性校验、失败回退、决策日志和四组消融实验。

居民自由文本输入、GIS 工具调用后的需求修订、多主体方案审议和规划行动卡自动生成已经完成产品流程与 Schema 设计，尚未形成完整可用功能。面试中我会明确区分这两部分。

## 三、系统架构与技术路线

### Q17：完整技术架构是什么？

**核心短答：**

系统分为五层：

1. 数据事实层：人口、POI、建筑、用地、路网和热环境；
2. 空间计算层：人口下沉、目的地核验、路径与逐道路边热压力；
3. 行为模拟层：居民类型、活动链、行为响应与活动失效；
4. LLM 推理层：需求转译、受约束决策、多主体审议和规划解释；
5. 规划评估层：设施匹配、运行约束、反事实验证和可视化。

各层通过结构化表和 JSON 传递，保证模块可以独立审查和替换。

### Q18：为什么采用模块化架构？

**核心短答：**

模块化能够解决三个问题：

- 空间事实、行为假设和 LLM 推断可以分别验证；
- 更换数据源、模型或参数时不需要重写完整系统；
- 出现错误时能够定位到数据、路径、行为、LLM 或设施运行模块。

这也便于向规划师解释哪些结果是观测事实、哪些来自模型计算、哪些仍需人工核验。

### Q19：端到端流程如何运行？

**核心短答：**

数据首先经过清洗、坐标统一和空间审查；随后将人口单元下沉至具有居住语义的步行入口，生成居民 Agent 与活动目的；目的地经过 POI、用地和路网可达性约束；系统计算真实道路路径和逐道路边热暴露，再生成高温行为响应与失效位置；LLM 对结果进行需求转译和解释；最后匹配清凉设施，并通过反事实与不确定性分析评价方案。

## 四、人口、OD 与行为模拟

### Q20：居民起点是随机生成的吗？

**核心短答：**

居民抽样具有随机性，空间分布受到真实数据约束。系统读取 2,073 个 WorldPop 人口统计单元，按照人口权重抽样，并依次将起点下沉到住宅 POI、住宅建筑步行入口或 OSM 步行节点。海淀区内起点保持在区内，人口权重守恒误差为 0。

当前形成 1,443 个正式可采样起点。代理点用于合成人口模拟，不代表真实居民家庭住址。

### Q21：如何保证目的地是真实地点？

**核心短答：**

目的地来自经过清洗的真实 POI，并同时接受五类约束：

1. 活动目的与 POI 类别、名称语义匹配；
2. EULUC 用地语境合理；
3. 位于可步行路网附近；
4. 与起点处于相同路网连通分量；
5. 满足活动最大出行距离，并按距离衰减抽样。

每个 OD 都保留来源和核验结果，当前 OD 来源追溯率为 100%。

### Q22：为什么需要七类居民 Agent？

**核心短答：**

热风险对不同社会角色的影响机制不同。分类同时考虑生命周期、身体脆弱性和活动约束，例如老年人更关注连续暴露与休息，儿童照护者受固定接送时间限制，户外劳动者无法轻易取消活动。分类用于产生差异化活动链、脆弱性和行为边界。

分类是研究原型中的角色抽象，后续需要通过人口统计、问卷和轨迹数据继续校准。

### Q23：为什么还要区分五类出行行为？

**核心短答：**

居民是否会停留或改变路线，主要受到活动必要性、时间刚性和路径灵活性影响。接送儿童与公园休闲即使经过相同高温道路，行为反应也不同。

五类行为包括固定时间必要出行、弹性必要出行、休闲出行、连续户外工作和陪护出行。每类行为对应不同允许动作，能够避免出现“接送途中随意取消”这类不合理模拟结果。

### Q24：行为动作是怎么选出来的？

**核心短答：**

结构化行为模型先根据热压力、脆弱性、活动必要性、时间刚性、路径灵活性、设施可达性、功能匹配、绕行成本和停留概率计算各动作分数，再通过 Softmax 转化为概率并抽样。

例如，高热压力、必要性和时间刚性同时较高，且附近设施不匹配时，`risky_completion` 得分会上升；热压力高、活动必要性低且时间灵活时，`cancel` 或 `delay` 的概率会上升。

### Q25：行为模型中的系数从哪里来？

**核心短答：**

当前系数属于透明的结构化先验，用于构建可运行的第一版机制。方向依据活动制出行理论、热风险行为研究和规划常识，数值尚未通过海淀区真实行为数据完全校准。

项目通过公开统计校准、内部有效性检查、多随机种子、单因素敏感性和蒙特卡洛分析控制误判风险。获得问卷、轨迹或设施使用数据后，再使用离散选择模型或贝叶斯校准估计参数。

### Q26：为什么没有直接使用 MATSim、SUMO 或其他开源仿真平台？

**核心短答：**

MATSim 和 SUMO 擅长交通系统运行、方式选择和网络流量模拟。当前项目关注步行活动全过程热暴露、活动失效语义和清凉设施规划，需要深度接入 LST、树冠、水体、居民脆弱性、设施功能匹配与 LLM 审议。

我借鉴了这些框架的合成人口、活动链、路网和事件日志思想，同时保留了针对热风险规划的轻量化模块，便于解释和快速迭代。未来需要模拟大规模交通均衡时，可以将活动与路径模块接入 MATSim。

## 五、路径与热暴露计算

### Q27：为什么要计算逐道路边热暴露？

**核心短答：**

同一条出行路径内部的热环境差异很大，居民经过不同道路的时间也不同。使用区域平均温度会掩盖局部无树荫路段和连续暴露问题。逐道路边计算能够识别哪一段路径贡献了主要暴露，并将结果直接转化为遮阴、饮水或休息节点需求。

### Q28：路径是如何生成的？

**核心短答：**

系统将 OSM 步行网络构建为 NetworkX 图，将起点和目的地吸附到最近可达节点。路径可以使用距离最短成本，也可以使用融合距离、热压力、遮阴缺口和水体距离的广义成本。输出会展开为有序道路边，并记录接入连接段。

当前正式模拟路径成功率为 100%，并通过节点连续性和距离守恒检查。

### Q29：环境感知路径会不会让居民绕行得不现实？

**核心短答：**

环境感知路径使用广义成本控制距离、热压力、遮阴和水体偏好，并由不同居民角色的绕行容忍约束。路径偏好参数仍属于情景参数，需要轨迹数据或规划师判断校准。因此结果用于比较不同机制和识别潜在路径，不直接声明为居民真实路线。

### Q30：热暴露公式是什么？

**核心短答：**

单条道路边的暴露为：

\[
Exposure_{g,e}=H_{e,t}\times \Delta t_{g,e}^{heat}\times V_g
\]

其中 \(H_{e,t}\) 是道路边在相应时段的有效热压力，\(\Delta t_{g,e}^{heat}\) 是居民经过该道路边时与高温时段重合的分钟数，\(V_g\) 是居民脆弱性权重。路径暴露对全部道路边求和，完整活动暴露还会加入目的地户外停留暴露。

### Q31：道路有效热压力如何计算？

**核心短答：**

基础热压力来自 LST 和典型高温日气象条件，树冠、行人遮阴代理和临近水体用于表达局地降温条件。缺失环境数据使用保守回退值，防止数据缺失路段被误判为凉爽路段。

树冠、水体等效应系数目前属于情景参数，因此项目对其开展敏感性分析，并明确不将其解释为实测降温效应。

### Q32：LST 与人体热舒适并不相同，为什么仍使用 LST？

**核心短答：**

LST 能够提供细尺度、连续的地表热环境差异，适合识别街区内部高温空间。它无法完整代表人体热舒适，因此项目加入 ERA5-Land 的逐时气象条件、人群脆弱性和户外停留时间进行修正，并将结果定义为用于规划比较的有效热压力。

如果后续获得更完整的气温、湿度、风速和辐射数据，可以进一步计算 UTCI 或 PET。

## 六、活动失效与设施规划

### Q33：什么叫“活动失效”？

**核心短答：**

活动失效描述居民在高温下无法安全、正常完成日常活动的状态，包括风险完成、延迟、替代、缩短、增加停留、取消或无法完成。它将“空间很热”转化为“某类居民的某项活动受到什么影响”，能够直接形成设施规划需求。

### Q34：如何判断失效发生在哪里？

**核心短答：**

系统按照活动全过程划分三个位置：

- 出发地：居民出门前或刚出发即面临障碍；
- 路径：途中连续或累计暴露过高；
- 目的地：到达、等候或停留阶段风险过高。

不同位置对应不同规划响应，例如社区服务下沉、路径遮阴节点或目的地短时等候空间。

### Q35：附近有设施为什么仍可能无效？

**核心短答：**

空间接近只代表潜在可达。设施要产生实际服务，需要同时满足功能匹配、开放时间、居民使用意愿、绕行容忍和容量条件。接送儿童的家长即使经过商场，也可能因为时间刚性和停留成本无法使用。

项目将设施实际干预效力表示为：

\[
OperationalEffect =
BaseEffect \times OpenMatch \times UseProbability \times CapacityFactor
\]

### Q36：如何验证设施方案有效？

**核心短答：**

采用反事实验证。在相同居民、活动、路径和高温情景下，分别模拟现状设施情景和加入推荐设施后的情景，对比活动服务覆盖率、暴露削减、失效活动恢复率、高风险活动解决率、开放时间匹配率和容量因子。

当前 20 个平衡网络设施情景的活动服务覆盖率为 21.88%。30 次蒙特卡洛实验中，覆盖率 P05 至 P95 为 18.23% 至 23.96%。

## 七、验证、准确性与可信度

### Q37：没有真实问卷和手机信令，怎么证明模拟是对的？

**核心短答：**

当前无法证明个体行为预测准确，因此我将验证拆成内部有效性、宏观校准、稳定性和外部验证四层。

目前已经验证 OD 来源、目的地语义、路径可执行性、距离与暴露守恒、规则合规、热响应方向和多随机种子稳定性。未来获得轨迹、问卷或设施客流后，再验证真实 OD、时间分布、行为动作和设施使用率。

这套表述能够清楚说明模型当前可信到什么程度，也避免把内部一致性包装成真实准确率。

### Q38：内部有效性 100% 代表什么？

**核心短答：**

它代表系统设定的七项内部检查全部通过，例如 OD 可追溯、路径成功、目的地距离合规和动作规则合规。它证明流水线内部逻辑一致、结果可执行和可审查，不代表居民真实行为预测准确率达到 100%。

### Q39：热压力与行为调整 Spearman 相关 0.674 说明什么？

**核心短答：**

该结果说明随着热压力升高，行为调整率呈显著上升趋势，模型产生了方向合理的热响应梯度。它属于机制合理性验证，不能证明每个居民的具体动作预测正确。

### Q40：为什么需要多随机种子分析？

**核心短答：**

居民类型、活动和行为动作包含随机抽样，单次运行可能受到随机种子影响。项目使用 5 个随机种子重复模拟，路径成功率始终为 100%。人均活动数量和平均路径距离较稳定，失效活动率变异系数达到 20.88%，说明正式汇报需要展示多次运行区间。

### Q41：为什么还要做蒙特卡洛分析？

**核心短答：**

设施使用概率、容量、服务半径和干预效力存在不确定性。蒙特卡洛分析通过在合理范围内联合扰动这些参数，输出方案收益分布，能够回答推荐方案在参数变化下是否仍然有效，也能避免给规划师一个看似精确的单点结果。

### Q42：哪个参数对结果最敏感？

**核心短答：**

当前单因素分析显示，服务半径对覆盖率和活动恢复率最敏感；使用概率和干预效力直接影响暴露削减；容量减半或活动客流扩展翻倍时，平均暴露削减会从 0.266 降至约 0.239，说明模型能够识别容量瓶颈。

### Q43：这个模型有哪些最大局限？

**核心短答：**

主要有四项：

1. 合成人口和代理起点无法替代真实居民 OD；
2. 高温行为参数仍缺少本地问卷与轨迹校准；
3. POI 难以完整表达设施规模、开放时间和真实容量；
4. 当前 LLM 消融样本较小，独立决策价值仍需强化验证。

项目通过透明先验、日志、敏感性分析和能力边界说明控制这些风险。

## 八、工程实现与产品化

### Q44：你在这个项目里具体负责了什么？

**核心短答：**

我负责从需求定义到研究原型落地的完整链路，包括：

- 定义高温活动失效这一产品问题；
- 设计 PRD、技术路线与 LLM 能力边界；
- 整理并核验人口、POI、用地、路网和热环境数据；
- 设计居民角色、活动链、行为响应和设施运行机制；
- 接入 DeepSeek 并设计约束、回退和消融实验；
- 建立内部验证、反事实、敏感性和不确定性分析；
- 搭建交互式展示页面并沉淀文档。

### Q45：项目中最难的技术问题是什么？

**核心短答：**

最难的是保证每项模拟活动从居民起点、目的地、道路路径、热暴露到 LLM 决策全部可追溯。任何环节出现虚假空间点、断线路径或模型幻觉，最终规划建议都会失去可信度。

我通过住宅语义入口下沉、POI 与用地双重核验、OSM 连通性审查、逐道路边展开、守恒检查、LLM 白名单和决策日志建立完整审查链路。

### Q46：为什么选择 Python、NetworkX 和 GeoPandas？

**核心短答：**

Python 生态能够同时覆盖空间数据、网络分析、行为模拟和 LLM API。GeoPandas 与 Rasterio 用于矢量和栅格处理，NetworkX 支持可解释的路径成本与逐边输出，Pandas 便于构建审查表和实验结果。研究原型阶段更看重机制透明、快速迭代和可复现性。

大规模生产环境下，路网部分可以迁移到 PostGIS、pgRouting 或更高性能图计算引擎。

### Q47：前端展示了什么？

**核心短答：**

前端使用 React、MapLibre GL 和 Recharts，展示诊断总览、典型居民活动路线、逐道路边热暴露、气象与内部核验、设施方案和反事实结果。页面的目标是让规划师能够从地图上的一条活动路线追溯到失效原因、设施需求和验证证据。

### Q48：如何保证项目可复现？

**核心短答：**

系统保存随机种子、参数配置、输入数据路径、运行元数据和决策日志；数据处理、行为模拟、LLM、设施评估和展示模块相互分离；完整流水线可以通过脚本重复运行。LLM 调用失败时自动回退，避免 API 状态使整个流程无法执行。

## 九、压力追问

### Q49：你的项目看起来只是把很多数据和模型拼在一起？

**回答：**

项目价值来自围绕同一规划决策构建可验证闭环。数据、行为模拟、LLM 和设施评估都服务于“活动在哪里失效、需要什么设施、实施后是否改善”这一条主线。每个模块拥有明确输入、输出、验证指标和能力边界，最终通过反事实结果检验规划响应。

### Q50：为什么不直接用热风险高值区做设施选址？

**回答：**

热风险高值区只表达环境危险程度，无法区分那里是否有人外出、从事什么活动、能否改变时间、是否愿意使用设施。活动失效需求可以识别固定时间必要出行、路径连续暴露和目的地等候等差异，设施也能够匹配具体功能。

### Q51：为什么不直接做一个传统机器学习预测模型？

**回答：**

当前缺少大规模、带真实行为标签的本地训练数据，直接训练预测模型容易得到缺乏可验证依据的准确率。项目当前采用透明规则和概率模型表达机制，通过敏感性和消融明确假设。获得问卷、轨迹和使用记录后，可以使用离散选择、梯度提升或贝叶斯模型进行参数学习。

### Q52：你有没有过度使用 LLM？

**回答：**

我主动限制了 LLM 的使用范围。空间计算、热暴露、路径、容量和最终规划决策都交给确定性模块或规划师。LLM 集中处理自然语言理解、复杂约束解释和多主体审议，这些任务具有明显语义推理需求。项目还通过消融实验检查 LLM 的实际增量。

### Q53：如果 DeepSeek API 不可用，系统还能运行吗？

**回答：**

可以。API 缺失、超时、JSON 解析失败或动作违规时，系统自动回退至结构化行为模型，并记录失败原因和决策来源。空间分析、行为模拟、设施评估和页面展示不依赖 LLM 在线可用。

### Q54：如果面试官认为 12 个活动的 LLM 消融样本太小，怎么回答？

**回答：**

这个判断合理。当前实验用于验证消融流程、约束机制和日志链路能够运行，无法支撑强统计结论。我会明确说明样本限制。下一步会建立覆盖人群、行为类型、热压力、绕行和设施冲突的分层测试集，扩大样本，并报告置信区间、分组表现和模型间一致性。

### Q55：如果让你下一步只做一件事，你会做什么？

**回答：**

我会优先完成居民自然语言诉求转译与 GIS 核验闭环。它最能体现责任规划师场景，也最能强化 LLM 的独立贡献。具体包括建立规划问题卡 Schema、事实与推断分层、GIS 工具调用、转译 Benchmark 和规划师评价实验。

## 十一、LLM 问题统一回答框架

面试官提出任何 LLM 深挖问题时，可以按照以下顺序回答：

1. **先讲任务价值**：LLM 解决哪类传统模块难以处理的语义或协商问题。
2. **再讲输入边界**：模型只接收哪些经过核验的结构化信息。
3. **再讲约束机制**：允许动作、JSON Schema、事实校验、日志和回退。
4. **再讲验证方式**：规则合规、事实一致、消融和用户评价。
5. **最后讲当前限制**：哪些贡献已经验证，哪些仍需要扩大样本或真实用户实验。

### 30 秒 LLM 标准回答

LLM 在项目中负责连接居民语言和规划模型。它将居民诉求转化为活动约束和设施需求，在结构化模型允许的动作集合内推演行为，并从不同利益主体视角审议方案。空间坐标、路径、热暴露和设施容量全部由 GIS 与规则模块计算。系统通过固定 JSON、动作白名单、事实校验、日志和自动回退控制幻觉，并使用消融实验验证 LLM 与结构化先验的实际贡献。

### 15 秒能力边界回答

LLM 负责语义理解、受约束推理和规划解释；GIS 与规则模型负责空间事实和数值计算；规划师负责最终决策。
