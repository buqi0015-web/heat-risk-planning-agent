# 逐道路边累计热暴露计算与审查说明

## 1. 计算目的

逐道路边累计热暴露用于替代统一 `heat_stress` 情景值，使活动失效判断能够反映居民实际经过道路的热环境差异。

## 2. 计算流程

```text
活动出发时间
→ 按路径顺序计算每条道路边进入与离开时间
→ 计算每条道路边与高温时段的真实重合分钟
→ 读取道路边 effective_heat_stress
→ 计算道路边热暴露
→ 按路径顺序累计
→ 加上目的地户外停留暴露
→ 驱动高温行为和活动失效判断
```

道路边暴露：

```text
segment_heat_exposure
= segment_effective_heat_stress
× segment_heat_overlap_minutes
× vulnerability_weight
```

活动累计暴露：

```text
before_exposure
= route_cumulative_heat_exposure
+ destination_dwell_heat_exposure
```

## 3. 缺失环境处理

- 道路边存在 `effective_heat_stress`：使用真实道路环境值。
- 道路边缺失环境值或属于起终点连接线：使用保守情景值 `0.70`。
- 目的地尚未建立独立环境值：户外停留使用情景值 `0.70`。

这些情景值属于待敏感性分析参数。

## 5. 已修复错误

1. 原实现按道路长度比例分摊高温重合时间，无法正确处理途中进入或离开高温时段。当前按路径顺序计算每段真实时间。
2. 原实现使用统一 `heat_stress` 计算暴露，道路环境只写入输出。当前道路环境直接驱动累计暴露、行为决策与失效判断。
3. 原 `route_segments.csv` 的 `cumulative_heat_exposure` 实际为单段暴露。当前改为走到该段结束时的路径累计暴露，并保留 `segment_heat_exposure`。
4. 原行为模型在暴露为 0 时仍可能随机产生延迟、缩短或取消。当前暴露为 0 时强制选择 `normal`，并跳过 LLM 行为决策。

## 6. 一致性审查

审查脚本：

```powershell
python scripts\audit_segment_exposure.py `
  --results outputs\haidian\agent_runs\segment_exposure_final_validation\agent_standalone_results.csv `
  --segments outputs\haidian\agent_runs\segment_exposure_final_validation\route_segments.csv `
  --output-dir outputs\haidian\validation\segment_exposure_final_audit
```

检查内容：

- 路径节点连续性。
- 分段长度之和与路径长度一致。
- 分段通行时间之和与路径时间一致。
- 分段高温重合时间之和与路径高温重合时间一致。
- 分段暴露之和与路径暴露一致。
- 路径暴露与停留暴露之和与活动暴露一致。
- 路径累计暴露单调递增。
- 热风险值处于 `0–1`。
- 暴露值不存在负数。

当前最终审查中，全部守恒检查、节点连续性检查和数值范围检查均为 0 错误。
